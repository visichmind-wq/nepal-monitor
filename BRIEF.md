**Регістр мови: про людей, не про облікові одиниці.** Це найважливіше правило тону після заборони спекуляцій. Сторінку читають ті, хто чекає конкретну людину, і кожне канцелярське слово про загиблих ранить без жодної потреби. Тому у ВЛАСНОМУ тексті сторінки не вживаємо: «партія» (тіл, людей — узагалі), «фрагменти тіл» (кажемо «неповні останки», і тільки там, де це потрібно для пояснення методики підрахунку), «автопсія» (кажемо «судово-медична експертиза» з поясненням, що вона й дає підставу для впізнання), «невпізнані тіла» (кажемо «ті, кого поки не впізнали», «поховані до впізнання»), «підняли тіло» (кажемо «знайшли», «винесли»), «тіла передали родичам» (кажемо «повернули родинам»), «ідентифікація» як самоціль (кажемо «впізнання»). Замість переліку районів із числами в дужках, який читається як інвентаризація, — просте перерахування без цифр, якщо цифри не несуть змісту.

Точність від цього не страждає: цифри, дати й статуси лишаються ті самі. Змінюється тільки те, як це звучить. І окреме виключення: у ПРЯМИХ ЦИТАТАХ офіційних повідомлень (розділ «Офіційно від України», формулювання МЗС і посольств) слова не правимо — це цитата, і підміна слів у цитаті гірша за різкий регістр.

Ще одна перевірка того самого класу: «про громадян інших країн серед упізнаних не повідомляли» — це не те саме, що «іноземців серед них немає». Коли джерело просто не згадує, пиши, що ні підтвердження, ні заперечення немає. Формулювання, яке звучить як заперечення, у такій ситуації — це вигадана інформація.

**Жодного жаргону без розшифровки.** Не використовуй нішевих термінів — ні рятувальних, ні військових, ні журналістських — без пояснення простими словами прямо в тому ж реченні. Якщо офіційне джерело каже «килимові пошуки», у тексті має бути «прочісують територію суцільно, ділянка за ділянкою». Якщо «rescue» і «recovery» — пояснити, що перше означає пошук живих, друге — пошук тіл. Читач не мусить гуглити терміни, щоб зрозуміти статус. Це стосується і сторінки, і короткого апдейту в чат.

Факти без інтерпретацій. Жодних припущень про долю конкретних людей понад те, що кажуть джерела. Без драматизації і без штучного оптимізму — нейтральна, спокійна мова.

**Не робити висновків типу «шанси зменшуються»** — це спекуляція, не аналітика. Фіксувати лише офіційно повідомлене: наприклад, зміну статусу операції з rescue на recovery, якщо таке офіційно оголошено.

Якщо публікуються списки загиблих — максимальна обережність: тільки офіційна ідентифікація вважається підтвердженням, попередні списки позначати як попередні.

Порожній результат — теж результат. Не заповнювати прогалини здогадками; писати чесно: «за запитом X у Tier 1–2 інформації не знайдено станом на [дата], перевірено: [перелік]».

- не використовуй `AskUserQuestion` — це автоматичний запуск, відповіді може не бути

Якщо комп'ютер недоступний і деплой не вдається — все одно зроби пошук і надішли текстовий апдейт, зазначивши в кінці, що сторінку оновити не вдалося.


## База фото для впізнання: перевірені адреси й що з ними не так у медіа

## Ланцюжок автоматичних запусків: тільки `send_later`, не `create_trigger`

Перевірено на власній помилці 05.09. Наступний зріз ставиться **лише через
`mcp__claude-code-remote__send_later`** — він лишає запуск у поточній робочій
сесії. `create_trigger` створює запуск у **чистій хмарній сесії**, а там немає
нічого з потрібного:

- немає `/home/claude/nepal-monitor` — ні `index.html`, ні `BRIEF.md`,
  ні `audit.mjs`, ні `node_modules` з Chromium;
- немає привʼязки до мака, якщо задача створена без неї, — отже й публікації;
- може не бути навіть інструментів вебпошуку.

Що сталося: вечірній запуск 04.09 поставив ранковий через `create_trigger`.
Той відпрацював 05.09 о 09:00 у порожній сесії, не зміг ні пошукати, ні
оновити файл, ні опублікувати — і поставив наступний вечірній у ту саму
порожню сесію. Ланцюжок жив, але не робив нічого. Виявилось це лише тому,
що Олесь спитав, чому сторінка стара.

Правило: у кроці 8 будь-якого зрізу — **тільки `send_later`**. Якщо в списку
задач зʼявився `create_trigger`-запуск на зріз, його треба видалити і
переставити через `send_later`.

**Якщо сесія все-таки почалась з нуля** (контейнер переробили, файлів немає) —
відновлюватись так, а не питати:

```
cd /home/claude && git clone https://github.com/visichmind-wq/nepal-monitor.git
cd nepal-monitor && npm install
```

Пуш із контейнера все одно заблокований проксі — публікація тільки з мака або
руками через GitHub. Але `git clone` і читання працюють, тож попередній стан
сторінки й `report-state` завжди можна підняти з репозиторію.

## Публікація без мака — з телефона

Якщо мака немає добу і більше, сторінка не мусить стояти. Олесь може
опублікувати сам: зберегти надісланий `index.html`, відкрити в браузері
`github.com/visichmind-wq/nepal-monitor` у версії для компʼютера, далі
**Add file → Upload files**, закинути файл із тією самою назвою і
**Commit changes**. Vercel збере автоматично. У застосунку GitHub це не
працює — тільки браузер. Кидати файл у дашборд Vercel НЕ можна: створиться
окремий деплой повз домен.
